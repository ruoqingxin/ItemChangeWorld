## 配置设定规则

以下规则适用于全部配置表，新增或修改配置时一并维护：

1. **字段归属明确。** 主表只保留公有属性，专属属性归对应子表；类别、类型、品质、级别等有限取值使用固定数值枚举。
2. **数字类型必须有批注。** 在枚举字段表头添加 Excel 普通批注（备注），完整列出“数字 = 中文含义”，例如 `1 = 武器、2 = 生命药`。批注正文只写中文含义，不附英文枚举名、程序代码或英文兼容提示，不使用线程批注。映射以 `__enums__.xlsx` 为准，枚举增删或改名时同步批注。`0/1` 开关及 `0 = 无`、`-1 = 修满` 等特殊数值也须说明含义。文字明确设为黑色、底色为浅黄色，按内容设置足够尺寸；必须保留备注图形及其关联，在 WPS 或 Excel 实际加载检查，不能仅以文件中存在批注文本判定可读。
3. **数字 ID 旁提供名称。** 对只有数字、无法直接辨认对象的 ID，在其右侧紧邻增加中文名称列。跨表引用、以主表 ID 关联的子表均适用；已有业务名称可直接辨认的记录不重复增加。名称根据对应 ID 的目标记录填写，不依据行号或排序推断。
4. **辅助名称不导出。** 名称列表头使用 `##物品名称`、`##技能名称` 等 `##` 前缀，`##type` 和 `##group` 行留空，中文说明标注“只读”。这些列只供配置阅读，不声明运行字段，不进入 schema 或二进制，不参与程序判断；业务引用始终以 ID 为准。
5. **辅助信息同步维护。** 修改目标名称、引用 ID 或枚举定义时，同时更新名称列与批注。新增或调整辅助列后使用 `gen_client.bat` 验证，纯阅读辅助改动不得改变运行字段结构和二进制数据；字段中文说明可以同步到生成代码的说明注释中。
6. **数据行按 ID 升序。** 按固定 `id` 的数值大小排列整行，新增数据插到对应编号位置，禁止直接追加在无关编号段后。排序不改变已分配编号，删除编号退役且不得复用；辅助名称、专属表、起始物品和掉落引用同步维护。
7. **字段说明使用中文。** 数据表第4行（`##`）使用明确中文解释字段用途、单位和必要的特殊值，禁止直接重复英文字段名，例如“品质”“允许属性档位上限”“品质耐久加成”。程序字段名、类型、枚举名和行为码保留原值；注册与枚举表的说明行及中文名称同样使用中文。

## 配置主键与引用

配置行使用固定正整数 `id`。技能、构筑、敌人保留独立 `code` 匹配程序行为，抽取顺序按固定 ID。物品分段：货币预留 `1–100`、武器 `101–300`、补给 `301–600`、完整功法典籍 `601–900`、材料与收藏品 `901–1200`、纳虚器 `1201–1500`。2026-11-19 用户明确授权本次从各类别区间起点连续重排，覆盖此前保留铁剑 `9` 和旧编号退役约定；之后排序、插行、改名不改编号，停用品编号不复用。本次字段整理保留所有已分配编号。

`equipment`、`potion_item`、`repair`、`stamina`、`container` 五张物品专属表的 `id` 均引用 `item.id`，分属上方现行工作簿；`potion.id` 为独立药效编号，`potion_item.potion_id` 指向 `potion.id`。`inventory_start.item_id` 和 `map_variant.item_id` 指向 `item.id`，自身条目 `id` 独立固定。`build_mutation.id` 引用 `build.id`，`skill_id` 引用 `skill.id`。`map_search.id` 引用搜索节点；`map_pool_weapon.id` 与两张权重表的 `pool_id` 引用 `map_pool.id`。地图节点通过 `pool_id` 引用掉落池，通过枚举 `kind` 判断节点类型。

`item.enabled` 为 `1` 时进入当前探索配置，为 `0` 时作为待投放数据导出。起始物品和掉落条目只引用已投放物品。编号变更的旧探索档按既有配置校验提示重新开局，保留原文。

### 预制体、脚本与路径

每个独立 UI 必须同时具备一个 `.lh` 和一个同名 TS 界面类文件，`<UIName>`、文件名和类名保持一致。新增界面按下列路径配对，路径字符串统一使用正斜杠：

| 对象 | 路径 |
| --- | --- |
| 主预制体 | `assets/ui/prefab/module/<模块名>/<UIName>.lh` |
| 主控制脚本 | `src/script/module/<模块名>/view/<UIName>.ts` |
| TS 的 `path` getter | `ui/prefab/module/<模块名>/<UIName>.lh` |

模块名与代码归属一致，例如 `UIShopView.lh` 对应 `UIShopView.ts` 和 `UIShopView`。复用公共片段继续放在既有 `assets/ui/prefab/common/<control>`，不为公共片段另建整屏生命周期或遮罩。既有预制体与模块目录的历史差异按具体任务核对，不据此批量移动资源。

### 基类与生命周期

- 沿用 `UIManager → UIBaseView → UIElements/ElementMapper`，不引入第二套界面系统。编写界面类前核对当前 `src/script/games/ui/UIBaseView.ts`，实现其抽象成员；当前包括 `layer`、`path` 两个 getter，以及 `onConstruct`、`onOpen`、`onClose`。
- `onConstruct` 统一缓存控件、初始化列表和绑定点击。`onOpen`、`onClose` 处理本界面打开、关闭的生命周期逻辑，不重复执行一次性初始化。
- `onOpen` 必须定义明确的参数名和类型，例如 `onOpen(intValue: number, strValue: string)`；无参数时显式使用 `onOpen()`，`...args` 仅用于基类定义。
- 刷新函数与事件响应函数分开，使用 `updateView`、`refreshXxx`、`onClickXxx` 等语义名称。

### ElementMapper 与节点访问

- 主预制根使用 `GWidget` 并挂载 ElementMapper。脚本通过映射访问的界面节点必须在 `.lh` 的 `elements` 中显式绑定。
- `getElement` 只允许传入已绑定的节点名，如 `this.getElement("txt_score")`；禁止 `this.getElement("panel/txt_score")` 等路径写法。
- 需要访问按钮内文本或其他子节点时，先在 ElementMapper `elements` 中单独绑定该子节点，再通过其节点名获取；不能用路径查找绕过绑定。
- 同一界面的映射范围内，节点名必须唯一且语义化，避免同名覆盖。新增节点按 `btn_`、`txt_`、`img_`、`list_`、`box_` 等语义前缀命名，公共预制的嵌套引用继续按现有作用域绑定。
- 在 `onConstruct` 一次性缓存所需节点到成员变量，后续业务直接使用成员变量，不在刷新或事件函数中反复 `getElement`。按控件类型沿用 `elems.getElement/getList/getUIButton` 等现有封装。

2026-11-20 用户针对储物界面明确允许通过父节点缓存组件内部子节点：页面仍显式映射固定容器、列表和业务入口；组件或列表项只在初始化时缓存自身背景、图片、文本等内部节点，动态格子和物品不逐个加入页面映射。此范围内覆盖上文要求按钮内部子节点逐一绑定的限制，不扩展为业务刷新时反复查找任意路径。

### 项目 List 与 ListItemCtrl

- `List` 必须通过 `this.elems.getList("list_name")` 获取，不能用 `getElement` 获取原始节点后代替项目列表封装。
- 在 `onConstruct` 设置 `itemCtrl`，并按场景设置 `isVirtual`；例如固定货币栏使用非虚拟列表。预制体包含 `GList` 及 `_templateNode` 列表项模板。
- 数据统一通过 `list.array = [...]` 绑定，不直接增删、修改内部 item 节点来代替数据更新。
- 需要列表点击时，使用 `list.setClickListener(this, this.onClickXxx)`，回调签名为 `(index: number, ctrl: XxxItemCtrl)`。`itemCtrl`、`isVirtual`、点击及其他一次性初始化必须在首次赋值 `array` 前完成。
- 列表项控制器使用 `XxxItemCtrl`，数据接口使用 `IXxxItemData`；继承当前 `src/script/games/uilib/ListItemCtrl.ts` 并遵循其参数约定。
- `setComponents(rootNode, index, ...)` 完成节点查找及一次性初始化；`update(data, index, ...)` 只负责渲染和状态刷新，禁止在其中重复执行一次性初始化。

### 创建与检查顺序

1. 确定模块和 `<UIName>`，检查同名 `.lh` 与 `.ts` 是否齐全，类名及 `path` 是否一致。
2. 搭建固定节点并配置 ElementMapper；缺少目标绑定时先补 `.lh`，再编写节点访问逻辑。
3. 在 `onConstruct` 缓存控件、绑定点击并完成列表初始化，再通过 `array` 提交数据。
4. 检查抽象成员、明确的 `onOpen` 参数、节点名与绑定、列表模板、列表点击和 ItemCtrl 生命周期；只按本次改动实际影响范围验证。

缺少 `.lh` 内容时，应明确说明需在 Laya 编辑器中创建或导出对应预制体，代码按规范路径引用；不能把只有 TS 的产物当作完整 UI 交付。本项目页面和弹窗仍使用 1280×720 横屏、`SCREEN_HORIZONTAL + SCALE_FIXED_AUTO` 及原生 adapter 关系，具体见第 08 号文档；不照搬象棋竖屏尺寸。资源改动继续按现有规则维护 `.meta` UUID 和依赖表。
