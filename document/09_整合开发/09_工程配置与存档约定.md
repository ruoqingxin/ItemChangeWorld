# 工程配置与存档约定

## 1. 位置与本轮核对范围

| 对象 | 位置 |
| --- | --- |
| 客户端 | `E:\NowChange\ItemChangeWorld` |
| 现行文档 | `E:\NowChange\ItemChangeWorld\document\09_整合开发` |
| 配置工程 | `E:\NowChange\config` |
| Excel 数据/声明 | 配置工程 `Datas`、`Defines`，以 `luban.conf` 为准 |
| 客户端生成代码 | 客户端 `src/script/config` |
| 客户端打包配置 | 客户端 `assets/config/configbin.bin` |
| 旧文档工作目录 | `E:\NowChange\config\document`，已停用为开发依据 |

本轮确认了目录、脚本、模块文件存在并读取导表/测试脚本；没有全面代码审计、编译、导表或重跑游戏测试。以下工程约定来自既有架构与新版已确认一致性要求，不据文件存在声称功能已验收。

## 2. 沿用项目分层

LayaAir 3.x + TypeScript，`src/script/module/<feature>` 组织业务；数据层用 `*Data.ts`，不新造 `*Model.ts` 习惯。沿用 `ModuleManager`、`BaseModule`、`UIBaseView`、`UIManager`、`EFuncID`、`EventEngine/Events` 等现有设施。

| 层 | 职责 |
| --- | --- |
| Module | UI、协议、红点、入口注册与登录/跨天生命周期 |
| Data | 运行时数据与已提交状态 |
| Manager | 跨界面流程、业务编排与事务入口 |
| View/Panel | prefab 绑定、交互与呈现，不另写战斗公式 |
| Ctrl | 子控件和列表项 |
| Utils | 纯规则、配置读取和辅助计算 |
| ProtoUtils | 已有网络场景的发包封装，不为本地首版额外造联网需求 |
| types/enum | 清晰的数据契约和枚举 |

当前相关模块为 `module/skillBattle`、`module/expedition`；新版战斗核文件在 `module/skillBattle/newRules/NewBattleCore.ts`。开工先核对现有职责、调用链和用户改动，不以旧树形提案重建整个工程。

道性、主动、被动与存档按已有模式扩展；不提前开发通用技能编辑器或复杂触发脚本系统。跨模块使用现有事件/导航，不把纯规则绑定到场景对象。

## 3. 配置链路

Excel 是人工维护源，经当前 Luban 声明与命令生成 TypeScript/bin，再由 `packall.js` 等现有流程打包并同步客户端；不是另建平行 JSON 运行时真源。

已读取 `gen_client.bat`：客户端目标为相邻 `..\ItemChangeWorld`，输出为 `output_client/code`、`output_client/data`，再复制配置包与代码。执行前仍需核查工作目录、实际目标、运行环境和变更范围。本次不执行。

- 普通主表 ID 从 1 开始，本表唯一，不要求全局唯一；已用 ID 保持兼容，不为整合重编号。
- 旧 `effect_group_id` 的 100xx/200xx 是排查来源约定，不自动扩成全项目统一 ID 分段。
- 通用物品字段与战斗字段分离，战斗细节放对应技能/效果/敌人等表，不把所有内容塞进 item。
- 通过实际生成的 `ConfigUtil.Tables` 与当前 schema 读取；旧 `*_config` 建议名及推荐 JSON 高号段不强制覆盖实际表。
- 先改源表/声明，再生成和核对；不手改 `schema.ts`、二进制或打包产物。
- 原型卡牌表、注灵物品、旧余额和数据保留，但不据其存在接回首版已取消/暂缓入口。
- 新地图、土道、物品、经济与成长字段，先提交相应内容表和映射，再接正式配置。旧运行时地图只是脚手架，不能当正式表已齐。

本目录 [基线 JSON](数据/已确认规则基线.json) 只是规则核对数据，非 Luban schema、非可直接导入配置，未知值为 null，测试区单列。

## 4. 存档边界

新版独立版本测试档，保留旧档备份，不静默迁移、清档、合并旧灵石余额、残卷、永久资格或活动局。测试夹具不等于正式赠送；显式重置仅针对指定测试档。

账号永久数据、实际库存/装备位置、本局构筑、地图/战斗、随机状态及结算记录各自有清晰归属。具体字段与存储实现由工程设计，不因本文强制换存储技术。

同局需恢复：两道与重抽记录、起始/当前候选、主动档位/被动/点数/道韵、敌人意图与血盾、玩家资源/耐久、地图位置/揭示/节点状态、箱内容与搜索进度、物品归属、恢复点使用、起点截止及已结算动作。

## 5. 一致性与幂等

行动、用药、移物、搜索揭示、拾取/丢弃、领奖、学习、交易、维修、终局结算分别界定完整提交边界。关联扣物、扣钱、资格变化、奖励入库和执行记录一起成功或失败，不半写。

随机候选与掉落一经确定就保存，关闭和恢复不重抽。重复请求、双击、重复广告回调和重复终局不能多扣、多奖或复制物品。保存失败要明确反馈，保留之前有效状态；已经流逝的现实时间不返还。

探索内每个有效提交检查截止。统一时间与恢复校验需覆盖改系统时间、后台、多窗口和离线；本地单机防篡改、跨端能力不能过度承诺。

- `tools/skill-battle-expedition.test.cjs`、`tools/skill-map.test.cjs`、`tools/skill-battle-supplies.test.cjs`

执行前阅读参数、编译依赖、服务端口及运行环境；不能只凭脚本文件名认定已接入统一测试。旧报告与新验收区别见 [12](12_冲突处理与历史进度.md)。
