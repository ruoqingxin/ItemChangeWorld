## 2. 沿用项目分层

LayaAir 3.x + TypeScript，`src/script/module/<feature>` 组织业务；数据层用 `*Data.ts`，不新造 `*Model.ts` 习惯。沿用 `ModuleManager`、`BaseModule`、`UIBaseView`、`UIManager`、`EFuncID`、`EventEngine/Events` 等现有设施。

| 层 | 职责 |
| --- | --- |
| Module | UI、协议、红点、入口注册与登录/跨天生命周期 |
| Data | 运行时数据与已提交状态 |
| Manager | 跨界面流程、业务编排与事务入口 |
| View/Panel | prefab 绑定、交互与呈现，不另写战斗公式 |
| Ctrl | 子控件和列表项 |
| Utils | 纯规则、配置读取和辅助计算 |
| ProtoUtils | 已有网络场景的发包封装，不为本地首版额外造联网需求 |
| types/enum | 清晰的数据契约和枚举 |

当前相关模块为 `module/skillBattle`、`module/expedition`；新版战斗核文件在 `module/skillBattle/newRules/NewBattleCore.ts`。开工先核对现有职责、调用链和用户改动，不以旧树形提案重建整个工程。

阶段 1 的接入前差异保留在 [实施清单](阶段1_接入差异与实施清单.md)。阶段 2 默认链为 `UIBaseView → NewBuildPanel（复用 NewBattlePanel）→ NewBuildSession/NewBuildRules → SkillBattleManager 新接口 → NewBattleCore`，保存重放使用相同规则。阶段 1 单场仅在开发预览 `?stage=1` 保留独立回归入口，游戏无新旧规则切换；两者都是新版核。

道性、主动、被动与存档按已有模式扩展；不提前开发通用技能编辑器或复杂触发脚本系统。跨模块使用现有事件/导航，不把纯规则绑定到场景对象。

## 3. 配置链路

Excel 是人工维护源，经当前 Luban 声明与命令生成 TypeScript/bin，再由 `packall.js` 等现有流程打包并同步客户端；不是另建平行 JSON 运行时真源。

`gen_client.bat` 的客户端目标为相邻 `..\ItemChangeWorld`，输出为 `output_client/code`、`output_client/data`，再复制配置包与代码。本轮按相同 Luban 参数分段执行，检查退出码后打包同步，不执行带 pause 且失败退出不可靠的批处理整体。

新增 `Datas/N-新版战斗配置表.xlsx` 的 rule/skill/passive/intent/enemy/potion 六张表及 `__tables__.xlsx` 注册。原配置工程 23 张表逐表字节不变；当前两端 29 表包与 schema 哈希一致。旧客户端独有的 item/skill 提案记录未回灌源表，不算获准内容。

阶段 2 在同一工作簿新增 earth_skill/build_passive/build_rule 三页并注册，当前共 32 张表。原 29 表块保持不变，不修改既有六页字段或 ID，不将默认资格当自动装配。阶段 1 上述 29 表数量属于此前交付；最新两端哈希与逐表核对见阶段 2 接入记录。

- 普通主表 ID 从 1 开始，本表唯一，不要求全局唯一；已用 ID 保持兼容，不为整合重编号。
- 旧 `effect_group_id` 的 100xx/200xx 是排查来源约定，不自动扩成全项目统一 ID 分段。
- 通用物品字段与战斗字段分离，战斗细节放对应技能/效果/敌人等表，不把所有内容塞进 item。
- 通过实际生成的 `ConfigUtil.Tables` 与当前 schema 读取；旧 `*_config` 建议名及推荐 JSON 高号段不强制覆盖实际表。
- 先改源表/声明，再生成和核对；不手改 `schema.ts`、二进制或打包产物。
- 原型卡牌表、注灵物品、旧余额和数据保留，但不据其存在接回首版已取消/暂缓入口。
- 新地图、土道、物品、经济与成长字段，先提交相应内容表和映射，再接正式配置。旧运行时地图只是脚手架，不能当正式表已齐。

本目录 [基线 JSON](数据/已确认规则基线.json) 只是规则核对数据，非 Luban schema、非可直接导入配置，未知值为 null，测试区单列。

## 4. 存档边界

2026-11-09 用户最新明确决定：本次清理所有旧游戏存档，不考虑兼容，不迁移旧余额、残卷、永久资格或活动局。覆盖此前“保留旧档备份”的约定。本次授权不是后续每次启动都重置新版进度。

旧探索脚手架使用 `nowchange.skill-expedition.current.v2`、版本 2，其既有清旧逻辑保留在旧适配器中；新版默认入口不实例化该适配器，不再次触发清理或迁移，不恢复旧 `v1` / `new-rules.v4`。

新版单场试炼使用独立键 `nowchange.stage1-battle.v1`、版本 1，不写现行 v2 或其他应用键，禁止 `localStorage.clear()`。保存开战 setup/initial、带时间戳的已提交动作、最终 state、起点/绝对截止及 timeout 原因。每次写入与恢复均使用同一新核完整重放核对，独立药品增加 revision 不增加 round/mainActions；写成功后才更新两份权威内存。跨战保留 HP/MP/武器耐久/药品库存，清战内标记。每个历史开战构筑独立保存，不拿后来配置覆盖历史。

阶段 2 独立键为 `nowchange.stage2-build.v1`、版本 1。保存配置/资格夹具快照、种子和随机状态、候选/构筑、点数/道韵、奖励来源、每场初始与最终快照，以及带时间戳的完整构筑/战斗命令账本。写入和恢复从起始同核重放，严格比较最终快照；默认入口另比较当前配置完整签名，不静默兼容改变配置的旧局。保存成功才发布状态，最后写前重新检查截止，写前原文比较拒绝旧页覆盖。

本轮不迁移、不清理阶段 1、v2 或其他键。新增阶段 2 损坏/不匹配档同样保留原文，UI 明确二次确认后仅删自身键。学书隔离模式写在本局夹具快照中，未创建/修改永久学习或真实库存。六场流程不承诺正式地图、跨端锁、可信时钟、防篡改或物品系统完成。

损坏、版本不符、快照不匹配或读写失败明确提示并保留原档；清除只允许 UI 二次确认后删除试炼键。写前比较原始文本，拒绝其他页面已更新的档，不覆盖较新修订。本地同步 localStorage 不是跨窗口强事务锁，不承诺跨端或防篡改。浏览器不同 origin、IDE 与正式平台存档隔离，本轮没有物理清除任何用户 v2 档。

已删除旧档字段补齐、线性三战转地图、忽略地图变化重写配置签名等迁移代码；版本、配置签名严格校验。新版档损坏或不匹配时明确阻止继续，使用显式重置，不伪装恢复成功。测试夹具仍不等于正式赠送。

账号永久数据、实际库存/装备位置、本局构筑、地图/战斗、随机状态及结算记录各自有清晰归属。具体字段与存储实现由工程设计，不因本文强制换存储技术。

同局需恢复：两道与重抽记录、起始/当前候选、主动档位/被动/点数/道韵、敌人意图与血盾、玩家资源/耐久、地图位置/揭示/节点状态、箱内容与搜索进度、物品归属、恢复点使用、起点截止及已结算动作。

## 5. 一致性与幂等

行动、用药、移物、搜索揭示、拾取/丢弃、领奖、学习、交易、维修、终局结算分别界定完整提交边界。关联扣物、扣钱、资格变化、奖励入库和执行记录一起成功或失败，不半写。

随机候选与掉落一经确定就保存，关闭和恢复不重抽。重复请求、双击、重复广告回调和重复终局不能多扣、多奖或复制物品。保存失败要明确反馈，保留之前有效状态；已经流逝的现实时间不返还。

探索内每个有效提交检查截止。统一时间与恢复校验需覆盖改系统时间、后台、多窗口和离线；本地单机防篡改、跨端能力不能过度承诺。

- `tools/skill-battle-expedition.test.cjs`、`tools/skill-map.test.cjs`、`tools/skill-battle-supplies.test.cjs`
