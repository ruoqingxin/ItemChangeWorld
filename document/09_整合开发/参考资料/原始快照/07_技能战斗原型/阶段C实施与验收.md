# 阶段 C：跨战斗物资与注灵实施与验收

日期：2026-11-04  
依据：《固定站位回合制战斗实施方案.md》阶段 C。  
状态：客户端、配置导出、自动化测试和 Laya 浏览器验证完成，待人工试玩反馈。

## 1. 本阶段交付

- 五格临战法囊，初始为火石、土石、疗伤丹、空、空。
- 每件物品是独立 `itemUid` 实例；不堆叠，消耗后格子清空，不自动补发或前移其他物品。
- 先选攻击招式，再点击火石或土石附带；再次点击可解除，更换或取消均不消耗。
- 确认前显示基础伤害、注灵伤害、护盾吸收、直接失血、施加灼烧、随后灼烧失血、玩家承伤、获得护盾和资源消耗。
- 确认时统一校验招式、剑势、物品实例和耐久。任一条件不满足，整条行动不执行。
- 注灵使用原属性石表的 100% 倍率与 5 耐久消耗；普通招式不耗耐久，耐久归零仍可出招。
- 火石施加 2 层灼烧，土石获得 4 护盾。
- 疗伤丹恢复最多 12 生命，满血禁用，占本回合唯一行动，随后敌人照常行动，不生成剑势。
- 胜利界面提供“携物继续”，将当前生命、铁剑耐久及原物品实例传到下一场。
- 新战斗清空护盾、剑势、灼烧和意图进度，不恢复生命、耐久或物品。
- 动画中锁定物品操作；跳过或关闭后恢复同一份已提交结果，不返还资源。

顶部“灵鼠新局 / 妖兔新局 / 守卫新局”和战后“重置测试档”均为显式测试模板重置，会恢复生命、耐久和三件测试物品，并生成新的实例 UID。它们不是正常继续入口，也不代表正式补给经济已经实现。

## 2. 精确规则

### 注灵与护盾

先结算基础伤害，再结算注灵伤害，两段共同消耗敌人护盾。

```text
注灵伤害 = floor(招式配置基础伤害 × damage_rate / 100 × 五行倍率)
```

五行倍率：克制 1.2、被克制 0.8、同属性 0.9、其他或无属性 1.0。金克木、木克土、土克水、水克火、火克金。

基础伤害已击杀目标时，不再追加注灵伤害或灼烧，但确认时选中的石头与耐久不返还。土行护盾仍产生，随后随胜利清空。

### 灼烧

- 只作用于敌人，层数可累加，上限 20。
- 在敌人阶段开始、执行意图前，对生命直接造成层数伤害，然后减 1。
- 本回合新施加的灼烧立即在接下来的敌人阶段生效。
- 打断不阻止灼烧结算；灼烧击杀立即胜利，不再执行敌人意图。
- 灼烧不消耗护盾，不生成剑势、不触发注灵。
- 战斗结束及进入下一场时清空。

### 原子提交

规则在状态副本上完成整回合计算，成功后 `SkillBattleManager` 一次替换正式快照。预览共用同一规则函数，使用选中时的 `battleId + revision` 确认令牌。

法囊实例与携带快照均深拷贝。重复确认、过期令牌、已消耗 UID、非法携带快照不会额外消耗资源。携带快照拒绝重复 UID、错误格数、稀疏数组、非物品内容、未知物品、不匹配武器及非法生命或耐久。

## 4. 客户端结构

客户端：`E:\NowChange\ItemChangeWorld`。

| 文件 | 职责 |
| --- | --- |
| `module/skillBattle/types/SkillBattleTypes.ts` | 物品实例、使用配置、法囊、灼烧、跨战斗携带数据、行动与事件 |
| `module/skillBattle/utils/SkillBattleConfigUtils.ts` | 读取并校验新物品使用表与既有物品、属性石表 |
| `module/skillBattle/utils/SkillBattleFormulaUtils.ts` | 注灵、用药、灼烧、全部成本校验和纯规则计算 |
| `module/skillBattle/manager/SkillBattleManager.ts` | 独立新战斗与携带快照初始化，原子提交 |
| `module/expedition/manager/ExpeditionManager.ts` | 阶段 C 的最小携物继续协调，只允许胜利后进入顺序相邻的下一场 |
| `module/skillBattle/view/SkillBattlePresenter.ts` | 法囊选择、附带切换、原始行动与令牌、资源事件播放快照 |
| `module/skillBattle/view/SkillBattlePanel.ts` | 五格法囊、注灵及用药预览、灼烧与治疗反馈、携物继续 |

表内顺序决定下一场是否允许进入；不能从第一战直接跳到第三战，也不能在失败或尚未获胜时继续。重复点击携物继续不会再次进入或复制物资。

本阶段 `ExpeditionManager` 不保存一份重复的物资副本，继续时从当前正式战斗快照提取携带数据，避免多个资源状态来源。
