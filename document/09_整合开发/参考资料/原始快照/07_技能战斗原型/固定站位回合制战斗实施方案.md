# 《末法寻仙》固定站位回合制战斗实施方案

版本：V0.1  
日期：2026-11-04  
用途：作为放弃卡牌后的新战斗原型开发依据。  
状态：2026-11-04 已确认以本文为实施依据，按阶段推进。阶段 A、B、C、D、E 已完成代码、自动化验证与 Laya 浏览器预览，待人工试玩反馈；具体数值仍为测试值，不代表正式平衡已定稿。阶段 E 于 2026-11-05 完成收藏解锁、统计与平衡探测，见《阶段E实施与验收.md》《阶段E平衡测试报告.md》。下一轮先验证战斗节奏与策略重复，不自动扩展完整成长系统。

后续讨论（2026-11-05）：用户试玩反馈“觉得可以”，随后进入小说设定融合讨论。已确认的主角身份、实体 / 虚影仓库方向及待定问题见[《小说融合规则讨论纪要》](../08_小说设定融合/小说融合规则讨论纪要.md)；该纪要尚未实施，不代表本文下述原型已支持新物品经济。

## 1. 方案结论

采用“固定站位、一对一、敌人意图可见、玩家每回合选择一次行动”的技能战斗。

第一轮可玩内容：

- 玩家在下、敌人在上，双方不进行自由移动。
- 一把铁剑，四个主动招式，共用剑势。
- 三种敌人、三场连续战斗。
- 两次战后强化选择，每次三选一。
- 战后可以继续深入或直接撤离。
- 生命、物资和耐久跨战斗保留；剑势等战斗状态不保留。
- 属性石和疗伤丹从五格临战法囊使用。
- 成功撤离后结算战利品；失败丢失本局未带出战利品。

核心验证问题：

> 玩家能否根据敌人意图、双方生命、剑势和剩余物资，改变行动选择，而不是重复固定顺序？

这不是完整商业版本。第一轮不承诺已经验证完整修仙成长、背包经济或长期平衡。

## 2. 新旧规则的关系

### 2.1 已确认的方向

- 放弃卡牌作为战斗载体。
- 先采用固定站位、回合制、四招式、剑势和敌人意图的方案。
- 搜打撤、修仙、肉鸽仍是整体游戏方向。
- 已确认分阶段实施，先完成阶段 A 纯逻辑战斗，再进入阶段 B 界面。

### 2.2 本文建议替换的旧战斗规则

| 旧规则 | 新原型建议 |
| --- | --- |
| 武器提供基础牌组 | 武器提供可用招式列表 |
| 抽牌、手牌、弃牌、洗牌 | 不进入新原型 |
| 每回合 3 行动点、可连续出牌 | 每回合只执行一个主行动 |
| 使用冷却、自动普攻推进战斗 | 不做自动普攻，也不做技能冷却 |
| 灵力、行动点、剑势多资源并存 | 第一轮只保留剑势作为招式资源 |
| 属性石拖到手牌上注灵 | 选择攻击招式时附带一个属性石 |
| 拖拽成功立即消耗，可能随弃牌浪费 | 预览不消耗；确认行动时统一校验并消耗 |
| 回合结束未出的注灵牌失去注灵 | 不再存在待出卡牌和跨回合注灵状态 |

最后两项是本次重设计提出的新消耗时机，不能与旧卡牌定稿同时使用；编码前应确认采用本文方案。

### 2.3 建议继续保留的原则

- 所有物品按独立实例管理，不堆叠。
- 战斗中不打开完整背包，只使用临战法囊。
- 普通攻击不消耗武器耐久，只有注灵消耗耐久。
- 耐久归零仍可使用基础招式，只是不能注灵。
- 灵石是局外货币数值；秘境获得的灵石袋必须撤离后打开。
- 局内强化在本次秘境有效，局外收藏负责长期解锁。
- 不靠打怪直接增加角色修为；修为仍来自资源转化，完整境界系统后续接入。

## 3. 核心体验与范围

### 3.1 三种玩法各自负责什么

| 玩法 | 本原型中的表现 |
| --- | --- |
| 搜打撤 | 生命和物资持续消耗，战利品尚未入库，战后决定继续或撤离 |
| 修仙 | 铁剑招式、五行注灵、功法残卷，以及撤离后收藏解锁 |
| 肉鸽 | 战后随机强化招式关系，强化本局有效，不同局形成不同打法 |

### 3.2 明确不做

自由移动、寻路、实际弹道碰撞、距离判定、即时操作、技能吟唱取消、暂停指令队列、多人联网、PVP、多敌人、速度和先攻、多武器、暴击闪避、完整五行状态、复杂装备词条、完整炼丹和境界、完整仓库与格子背包。

第一轮也不做通用技能编辑器或复杂触发脚本系统。

### 3.3 不能用原型证明的事情

- 六格简化战利品袋不能验证正式背包空间博弈。
- 只有两颗属性石不能证明耐久消耗已经平衡。
- 三场固定遭遇不能证明长期重玩性。
- 收藏解锁不能替代完整修仙境界成长。

这些内容应在战斗成立后逐项加入，不能在验收时混为一谈。

## 4. 玩家、招式与剑势

### 4.1 初始玩家

| 项目 | 测试值 |
| --- | --- |
| 最大生命 / 初始生命 | 50 / 50 |
| 初始护盾 | 0 |
| 初始剑势 / 上限 | 0 / 3 |
| 武器 | 破旧铁剑 |
| 武器最大 / 初始耐久 | 50 / 50 |
| 固定防御 | 0，第一轮不参与结算 |
| 暴击、闪避、速度 | 不启用 |
| 灵力池、行动点、技能冷却 | 不启用 |

每次进入下一场战斗，保留当前生命与武器耐久，剑势重置为 0。

### 4.2 四个招式

| skill_id | 招式 | 剑势消耗 | 效果 | 可注灵 |
| --- | --- | --- | --- | --- |
| 1 | 剑击 | 0 | 对敌造成 6 点基础伤害，获得 1 剑势 | 是 |
| 2 | 守势 | 0 | 获得 8 点护盾，获得 1 剑势 | 否 |
| 3 | 贯虹 | 2 | 对敌造成 14 点基础伤害 | 是 |
| 4 | 破势 | 2 | 对敌造成 8 点基础伤害；若当前敌人意图可被打断，取消该次意图 | 是 |

说明：

- 剑势最低为 0，最高为 3，超出部分直接舍弃。
- 剑势满时仍可使用剑击和守势，不额外转化溢出收益。
- 破势可以对普通攻击使用，但此时只有伤害，不取消敌人行动。
- 打断看 `interruptible` 标记，不根据招式名字猜测。
- 每次行动只能附带一颗属性石。
- 玩家不能重复使用招式，也不能在用药后再使用招式。
- 不提供“空过”按钮；查看说明和取消预览不推进回合。

### 4.3 为什么保留这四个招式

剑击负责主动输出，守势负责承受压力；两者都能积累剑势。

贯虹和破势争夺同一份剑势：前者争取击杀，后者避免危险。敌人剩余生命、下一招和玩家物资决定哪种投入更合适。

这只是待验证的设计假设。若守势总是最优，不能以“存在四个按钮”作为战斗成立的证据。

## 5. 精确回合顺序

### 5.1 战斗开始

1. 读取本局生命、武器、法囊和强化。
2. 初始化敌人生命、护盾、状态和意图序列。
3. 玩家护盾、剑势、临时增伤清零。
4. 敌人意图指针设为 0，确定并显示第一条意图。
5. 进入玩家选择阶段。

### 5.2 每个回合

1. 保持当前敌人意图不变，显示伤害、护盾或其他效果和可打断标记。
2. 玩家选择一个招式或一枚疗伤丹，查看结果预览。
3. 玩家确认；同时检查战斗阶段、剑势、物品实例、武器耐久和使用条件。
4. 校验失败则不改变任何资源，返回明确原因。
5. 校验成功则锁定输入，扣除剑势、属性石和对应耐久，或消耗疗伤丹。
6. 按固定顺序结算玩家行动和其附加效果。
7. 若敌人死亡，立即胜利，不再执行敌人意图和后续敌方状态。
8. 清除敌人上一次行动留下、且本次玩家行动后仍剩余的护盾。
9. 进入敌人阶段，先结算敌人的灼烧。
10. 若灼烧使敌人死亡，立即胜利。
11. 若敌人当前意图被打断，跳过该次意图；否则执行它。
12. 若玩家死亡，立即失败，不允许通过后续反击或用药复活。
13. 若本次玩家使用守势且满足反击条件，结算一次反击；敌人死亡则胜利。
14. 清除玩家剩余护盾和本回合打断标记。
15. 敌人意图指针前进一格；被打断的意图也视为已消耗，不留到下一回合。
16. 回合数加 1，显示下一条意图，恢复玩家输入。

同一条已展示意图不能在玩家确认后临时更换。

### 5.3 护盾存续

| 对象 | 获得时机 | 清除时机 |
| --- | --- | --- |
| 玩家 | 自己行动时，例如守势或土行注灵 | 本次敌人行动及反击结算后 |
| 敌人 | 自己行动时，例如石甲 | 下一次玩家行动结束后 |

敌人的护盾不能在获得当回合立即清空，否则它无法防御下一次玩家攻击。

如果敌人处于石甲保护下，玩家选择守势或用药，敌人护盾也会在该次玩家行动结束后清除。

## 6. 伤害、状态与预览

### 6.1 基础伤害

```text
基础伤害 = max(0, 招式配置伤害 + 本次满足条件的强化增伤)
护盾吸收 = min(当前护盾, 本段伤害)
生命损失 = 本段伤害 - 护盾吸收
```

第一轮不引入攻击面板倍率、固定防御、暴击、随机浮动或抗性。

角色成长以后可以增加这些维度，但必须重新评估数值，不直接叠到当前测试值上。

### 6.2 注灵伤害

```text
注灵伤害 =
floor(招式配置基础伤害 × damage_rate / 100 × 五行克制倍率)
```

- 基数只取招式配置值，不包含藏锋、破绽等临时增伤，避免放大关系不明确。
- 普通伤害先结算，注灵伤害后结算，共同消耗目标护盾。
- 五行克制只影响注灵伤害，不影响普通伤害。
- 武器自身五行暂不参与公式。
- 第一轮使用现有一阶普通石的 100% 测试倍率，后续根据消耗收益调整。
- 基础伤害已经击杀目标时不再向尸体追加伤害或状态，但已确认的注灵资源不返还。

| 关系 | 注灵伤害倍率 |
| --- | --- |
| 克制目标 | 1.2 |
| 被目标克制 | 0.8 |
| 同属性 | 0.9 |
| 其他 / 无属性 | 1.0 |

克制关系继续采用金克木、木克土、土克水、水克火、火克金。

### 6.3 第一轮只实装火、土两种属性石

这是为了缩小状态实现范围，不代表正式游戏取消其余五行。

| 物品 | 注灵倍率 | 耐久消耗 | 额外效果 |
| --- | --- | --- | --- |
| 一阶普通火属性石 | 100% | 5 | 对存活敌人施加 2 层灼烧 |
| 一阶普通土属性石 | 100% | 5 | 玩家获得 4 护盾 |

额外效果在本次伤害之后结算。土行护盾不依赖敌人是否仍存活，但胜利时会随战斗状态一起清除。

第一轮只做灼烧：

- 仅用于敌人，玩家灼烧后续再接。
- 在敌人阶段开始、执行意图之前结算，包括被打断的回合。
- 对生命直接造成等同层数的伤害，不消耗护盾。
- 结算后层数减 1，最低为 0。
- 本回合新施加的灼烧会在紧接着的敌人阶段生效。
- 层数可累加，测试上限 20；战斗结束后清除。
- 灼烧不视为武器攻击，不产生剑势、不触发注灵和反击。

### 6.4 显示与真实结算

玩家选择招式和属性石后，显示：

- 剑势消耗及行动后的剑势。
- 基础伤害、注灵伤害、护盾吸收和直接生命损失。
- 本次获得的护盾。
- 敌人是否会被打断。
- 即将施加的灼烧，以及敌人阶段开始时预计触发的灼烧伤害。
- 物品和耐久消耗。

“直接伤害”和“随后灼烧”分开显示，不混为一个无法解释的伤害数字。

预览和执行必须共用同一个纯规则函数。预览在状态副本上计算，不修改正式战斗状态、不扣资源、不消耗随机数。

## 7. 三种测试敌人

所有数值先固定，不叠等级、攻击面板或随机倍率。`enemy.atk` 不再与意图伤害重复相加。

| 敌人 | 生命 | 五行 | 循环意图 |
| --- | --- | --- | --- |
| 腐化灵鼠 | 24 | 木 | 爪击 6 → 爪击 6 → 啃咬 8 |
| 赤眼妖兔 | 30 | 火 | 冲撞 7 → 蓄力 → 猛撞 14 → 冲撞 7 |
| 灵田守卫 | 40 | 土 | 横扫 8 → 石甲 6 护盾 → 裂地重击 14 |

规则：

- 灵鼠所有意图不可打断，用于测试基础攻防和物资节省。
- 妖兔“蓄力”只展示其下次将释放重击，本回合不造成伤害，也不额外叠加攻击倍率。
- 妖兔只有“猛撞”可打断；提前对“蓄力”使用破势不能跳过下一回合的猛撞。
- 守卫“石甲”护盾保留到下一次玩家行动结束。
- 守卫只有“裂地重击”可打断。
- 所有意图均为确定性循环；第一轮不做随机 AI、血量阶段切换和召唤。

首轮可以把普通战斗约 4～7 回合作为观察区间，精英允许更长。它是待校准目标，不是当前数值已经达到的结论。

## 8. 两次三选一强化

### 8.1 强化列表

| upgrade_id | 名称 | 建议测试效果 | 初始可出现 |
| --- | --- | --- | --- |
| 1 | 反击 | 守势实际吸收敌人攻击伤害后，玩家存活则反击 3 伤害，每回合一次 | 是 |
| 2 | 藏锋 | 使用剑击前剑势已达上限时，该次剑击基础伤害 +4 | 是 |
| 3 | 余势 | 贯虹剑势消耗由 2 降至 1 | 收藏测试残卷后 |
| 4 | 破绽 | 成功打断后，本场下一次剑击伤害 +6；不叠加，触发后消失 | 收藏测试残卷后 |
| 5 | 厚土 | 守势护盾从 8 提高到 11 | 是 |
| 6 | 火种 | 火属性石施加的灼烧层数 +1 | 是 |

细节：

- 每个强化本局最多获得一次。
- “反击”只由守势行动触发，土行注灵获得的护盾不触发它。
- 实际吸收量大于 0 才算触发；敌人休整、被打断、零伤害均不触发。
- 反击可以被敌人护盾抵挡，不视为招式，不积累剑势、不附带注灵、不触发另一轮反击。
- 藏锋在执行剑击、获得剑势之前判断，不能用本次新获得的剑势满足条件。
- 破绽不跨战斗保留；再次成功打断只是保持 +6，不累加为 +12。
- 余势应直接改变预览和实际剑势消耗，不能只在行动后偷偷返还。
- 火种可能在火属性石耗尽后无用；本轮允许玩家不选它，后续再决定是否加入候选条件过滤。
- 强化不相互递归触发，只实现本表明确列出的关系。

### 8.2 候选生成

1. 第 1、2 战胜利后，各生成一次三选一。
2. 从本局允许且尚未获得的强化中，等概率无放回抽取 3 个。
3. 候选不足 3 个则全部展示，不能死循环补齐，也不能重复展示同一强化。
4. 玩家选择一个，另外两个不进入本局；不提供刷新。
5. 同一次奖励重复打开时仍使用已保存候选，不能重抽。
6. 选择完成后才进入继续 / 撤离界面。
7. 第 3 战后直接结算，不再展示没有后续战斗可用的强化。

普通测试模式可以直接开放全部六个强化；正式闭环初始开放四个，带回并收藏残卷后开放另外两个。

这只是最小的收藏解锁验证，不代表已经实现正式借法系统。

## 9. 物资、注灵与死亡

### 9.1 初始五格法囊

| 格子 | 内容 |
| --- | --- |
| 1 | 一阶普通火属性石一颗 |
| 2 | 一阶普通土属性石一颗 |
| 3 | 疗伤丹一枚 |
| 4 | 空 |
| 5 | 空 |

同名物品也必须是不同 `itemUid`，不使用数量堆叠。

调试入口可以每次新开一局时重置测试物资；局内连续战斗和恢复存档不能重新补发。调试补发不能当作正式经济来源。

### 9.2 属性石操作

1. 选择可注灵招式。
2. 点击法囊中的属性石，作为本次行动附带资源。
3. 预览变化，可取消或更换，尚不消耗。
4. 点击确认后，统一校验并消耗属性石、耐久及剑势。
5. 招式结算完成后，不保留任何待释放注灵状态。

不做拖拽，不需要选择敌人，因为当前只有一个敌人。

如果物品不存在、武器耐久不足或剑势不足，整条行动都不执行。不能扣了一颗石头后才发现技能不可用。

### 9.3 疗伤丹

- 使用后恢复 12 生命，不能超过最大生命。
- 用药占用本回合唯一主行动，随后敌人照常行动。
- 满血时禁止使用，不消耗物品、不推进回合。
- 用药不积累剑势，不触发武器招式强化。
- 初版只允许在战斗中使用，不在战后提供无代价用药入口。

### 9.4 耐久

- 只在成功确认注灵行动时扣除 5 耐久。
- 不足 5 时禁止注灵，但基础招式继续可用。
- 耐久跨战斗保留，不自动回复。
- 不做战斗修理、永久耐久损毁和武器碎裂。
- 初始两颗石头最多消耗 10 耐久，不能据此判断 50 耐久是否合适。
- 必须额外用“当前耐久 4、5、0”和“多颗属性石”调试数据验证边界。

### 9.5 失败与撤离

| 内容 | 成功撤离 | 秘境失败 |
| --- | --- | --- |
| 本局临时战利品 | 入库 | 丢失 |
| 未消耗法囊物品 | 保留 | 丢失 |
| 已消耗物品 | 不返还 | 不返还 |
| 装备中的铁剑 | 保留 | 原型阶段保留 |
| 已损耗耐久 | 保留损耗 | 保留损耗 |
| 本局强化 | 清除 | 清除 |
| 局外收藏和货币 | 不减少 | 不减少 |

失败保留铁剑是降低原型复杂度的保护规则，不代表正式版装备死亡掉落已经定稿。

只有战后允许撤离，不做战斗中逃跑、读条撤离或被打断撤离。

## 10. 三场秘境与最小局外成长

### 10.1 路线

```text
新建测试秘境
  → 第 1 战：腐化灵鼠
  → 暂存奖励，强化三选一
  → 撤离 / 继续
  → 第 2 战：赤眼妖兔
  → 暂存奖励，强化三选一
  → 撤离 / 继续
  → 第 3 战：灵田守卫
  → 暂存奖励，完成并撤离
```

一旦玩家选择继续并进入下一战，就不能再回到上一次胜利界面撤离。

### 10.2 固定奖励

| 胜利场次 | 临时战利品 |
| --- | --- |
| 第 1 战 | 小灵石袋一个，撤离后使用获得 15 灵石 |
| 第 2 战 | 小灵石袋一个，撤离后使用获得 25 灵石 |
| 第 3 战 | 灵石匣一个，撤离后使用获得 40 灵石；试炼剑诀残卷一本 |

第一轮固定奖励用于排查逻辑。掉率、稀有度和随机掉落不在这轮一起调。

- 战利品自动进入本局六格简化战利品袋。
- 每个战利品占一格，不堆叠，不与临战法囊混用。
- 完整路线只产生四件物品，本轮不会触发背包满。
- 不做尺寸、旋转、丢弃、自动整理和正式仓库界面。
- 只有撤离后才将这批物品转移到局外简单列表。
- 灵石袋和灵石匣在局外由玩家点击打开，不能在局内自动变成货币。

### 10.3 收藏解锁

成功带出“试炼剑诀残卷”后，玩家点击收藏：

- 消耗一个残卷实例。
- 永久设置该功法的收藏标记。
- 后续秘境的强化候选池新增“余势”和“破绽”。
- 已收藏时再次操作应明确提示，不重复消耗。
- 重复残卷暂时留存，不做共鸣、出售或分解。

这里仅用一个收藏解锁证明长期收获能影响下一局。正式借法、修为、筑基和炼丹单独设计，不在这轮暗中加入。

### 10.4 新一局恢复

原型测试据点允许点击“开始新一局”时将生命恢复到最大值；不消耗局外货币。

测试物资由 Debug 模板补发，耐久也可由显式“重置测试档”恢复。正常继续同一局时绝不能触发这些恢复。

正式出战补给、维修费用和角色恢复方式留待经济系统阶段处理。

## 12. 程序结构

### 12.1 沿用项目约定

继续使用 Laya 3.x、TypeScript 和 `Module / Data / Manager / View / Utils` 分层。

当前工作区是配置工程，不是完整游戏源码。本次只检查了配置工程和已有说明，未检查客户端战斗实现；下面是建议职责，不代表现有客户端类必须全部替换。

```text
module/battle/
  BattleModule.ts
  BattleManager.ts
  BattleEvent.ts
  data/BattleData.ts
  types/BattleTypes.ts
  utils/BattleConfigUtils.ts
  utils/BattleFormulaUtils.ts
  utils/BattleDebugUtils.ts
  view/UIBattleView.ts

module/expedition/
  ExpeditionModule.ts
  ExpeditionManager.ts
  data/ExpeditionData.ts
```

| 部分 | 职责 |
| --- | --- |
| BattleModule | 注册模块、界面和跨模块事件 |
| BattleData | 当前战斗快照，不直接调用 UI |
| BattleManager | 接收操作，校验行动，推进状态，发布结果 |
| BattleFormulaUtils | 纯规则计算，产出下一状态和结算事件，支持预览 |
| BattleConfigUtils | 将现有配置转换成战斗所需数据，不读 UI |
| BattleDebugUtils | 创建固定玩家、敌人、种子和边界测试数据 |
| UIBattleView | 显示状态、收集操作、播放事件，不自己计算伤害 |
| ExpeditionData / Manager | 跨战斗生命、物品、强化、临时奖励和撤离结算 |

一场战斗的计算与秘境进度分开；不能在切换战斗时把整局物资初始化一遍。

### 12.2 最小运行时数据

```typescript
type BattlePhase =
    "player_input"
    | "resolving"
    | "victory"
    | "defeat";

interface CombatantRuntime {
    hp: number;
    maxHp: number;
    block: number;
}

interface BattleState {
    battleId: string;
    phase: BattlePhase;
    round: number;
    player: CombatantRuntime;
    enemy: CombatantRuntime;
    swordQi: number;
    swordQiMax: number;
    enemyId: number;
    enemyIntentIndex: number;
    enemyBurn: number;
    nextSlashBonus: number;
}

type BattleAction =
    | {
        type: "skill";
        skillId: number;
        stoneItemUid?: string;
    }
    | {
        type: "use_item";
        itemUid: string;
    };

interface ItemInstance {
    itemUid: string;
    itemId: number;
}

interface ExpeditionState {
    runId: string;
    seed: number;
    rngState: number;
    encounterIndex: number;
    phase: "battle" | "reward" | "decision" | "extracted" | "failed";
    playerHp: number;
    playerMaxHp: number;
    weaponUid: string;
    weaponId: number;
    weaponDurability: number;

    loot: ItemInstance[];

    pendingUpgradeChoices: number[];

```

这些类型是边界示意，具体命名以客户端现有约定为准。

还需要一个局外测试存档，保存收藏标记、货币、仓库物品和已完成结算的 `runId`。

### 12.3 建议接口

```typescript
previewAction(snapshot, action): ActionPreview
resolveAction(snapshot, action): ActionResolution
startBattle(expedition, encounterConfig): BattleSnapshot
finishBattle(expedition, battleResult): ExpeditionState
createUpgradeChoices(expedition): number[]
chooseUpgrade(expedition, upgradeId): ExpeditionState
extract(expedition, profile): SettlementResult
fail(expedition, profile): SettlementResult
```

行动快照要包含战斗状态、武器耐久、法囊实例和本局强化，不能只传生命和技能 ID。

`resolveAction` 必须先完整校验，在副本上计算成功结果，再统一提交。不能执行到一半抛错，留下“物品已扣、伤害未生效”的状态。

### 12.4 随机、存档和结算

- 战斗本身不随机；强化候选使用保存的种子和随机状态。
- 生成候选后保存实际候选 ID，读档不重新抽。
- 单机原型只在完整行动结算后、奖励生成后、选择强化后等安全节点存档，不保存半段动画。
- 关闭动画或界面不等于取消已经提交的行动。
- 撤离时检查 `runId` 是否已结算；战利品入库和结算标记应写入同一份完整存档快照。
- 失败也要设置终止状态，不能读回旧战后界面再次撤离。
- 该方案针对本地单机调试，不承诺防修改存档或联网防作弊。

### 13.3 现有配置的复用与停用

| 现有表 | 处理建议 |
| --- | --- |
| item | 复用显示、分类、品质、占格；当前生成字段是 item_type、des，不直接照旧文档写成 main_type、desc |

| status | 先检查现有时机是否匹配本文灼烧，不能未经核对直接套用 |
| battle_rule、card、deck、deck_card | 保留旧数据供对照，新原型不读取 |
| enemy_intent | 保留旧卡牌测试；新原型采用明确排序的独立意图步骤配置 |

当前属性石生成结构使用 `purity_min / purity_max`，不要根据旧文字说明擅自改为单个 `purity_value`。

物品和武器战斗字段继续分表维护，不把招式伤害塞进物品表。

### 13.4 避免第一轮配置过度通用化

四个招式只需要伤害、护盾、剑势和打断几种固定规则；六个强化可以用有限的 `effect_kind` 枚举实现。

暂不设计任意条件表达式、脚本字符串或嵌套触发树。

如果客户端已有可靠效果执行器，应先评估复用。但不能为了复用卡牌逻辑，继续依赖手牌实例、抽牌堆或出牌事件。

### 13.5 导表约束

- 正式改表前备份或提交当前工作，不覆盖用户已有改动。
- 更新 Excel 与必要的表声明后，通过现有工具生成代码和数据。
- 不直接编辑 `output_client/code/schema.ts`，也不手工修改 `.bin`。
- 运行 `gen_client.bat` 前确认它会覆盖的客户端目标目录；该脚本包含复制生成物的步骤。
- 先验证四个招式、三条遭遇和十条意图步骤均可被配置 API 正确读取。
- 新原型和旧卡牌原型用独立入口区分，避免旧战斗误读新规则。

## 14. 开发顺序与交付物

### 阶段 A：纯逻辑战斗

范围：一把铁剑、四招式、三敌人、意图和剑势，不接 UI、物品、强化、掉落。

- 预览与正式结算共用的规则函数。
- 关键边界自动化测试。

### 阶段 B：最小战斗界面

范围：上下站位、四招式、意图、资源显示、预览、确认和反馈。

- 占位立绘、短位移、受击和伤害数字。
- 结算中锁定输入与动画完成恢复。
- 胜利 / 失败界面。

验收：不用控制台也能完成一场战斗；跳过动画不改变结果。

### 阶段 C：跨战斗物资与注灵

范围：五格法囊、火土属性石、疗伤丹、耐久和灼烧。

- 招式附带属性石操作。
- 原子资源校验与消耗。
- 疗伤丹占行动的流程。
- 生命、物资与耐久跨战斗保留。

验收：同一批物资从第一场带到第三场，不能重复生成或返还。

### 阶段 D：三战、强化与撤离

范围：三场连续战斗、两次强化、固定奖励、撤离和失败清算。

- 简化秘境流程和强化三选一。
- 临时战利品袋与局外简单物品列表。

- 最小存档。

验收：可以第一战后撤离，也可以挑战第三战；失败不能把临时战利品带出。

### 阶段 E：收藏解锁与调参

范围：残卷收藏、下一局候选池变化、测试统计。

交付物：

- 收藏标记和新强化解锁。
- 行动日志、战斗统计、平衡测试报告。
- 确认下一轮是否值得扩展武器、借法、背包和修仙成长。

验收：获得残卷、撤离、收藏、再开一局后，确实出现新的构筑选择。

不在缺少客户端代码、现有效果模块和资源情况时承诺准确工期。第一阶段结果出来后再估算后续工作量。

| 耐久 4 注灵 | 整条行动失败，不扣剑势和物品 |
| 耐久 5 注灵 | 正常执行，耐久归零 |
| 耐久 0 普通攻击 | 允许 |
| 取消待注灵行动 | 不消耗任何资源 |
| 贯虹对土敌使用火石 | 基础 14、注灵 14；火土无克制关系 |
| 贯虹对火敌使用火石 | 基础 14、注灵 floor(14×0.9)=12 |
| 敌人 6 护盾承受剑击 | 生命不变，护盾归零，玩家正常获得剑势 |
| 敌人 6 护盾下玩家使用守势 | 玩家行动结束后敌人护盾清空 |
| 破势取消重击 | 重击不造成伤害，下一回合进入下条意图 |
| 破势攻击普通爪击 | 敌人存活时仍会执行爪击 |
| 对妖兔“蓄力”使用破势 | 不取消下一回合的猛撞 |
| 打断且敌人有灼烧 | 灼烧正常结算，然后跳过意图 |
| 敌人被直接攻击或灼烧击杀 | 立即胜利，不再出招 |
| 玩家被攻击击杀且有反击强化 | 立即失败，不反击复活 |
| 守势面对蓄力 / 被打断 | 不触发反击 |
| 反击击杀敌人 | 正常胜利，不重复结算 |
| 满血使用疗伤丹 | 禁止，不推进回合 |
| 确认按钮快速连点 | 只产生一条行动和一次消耗 |
| 读档或重复打开强化界面 | 候选不变、强化不重复领取 |
| 多次调用撤离结算 | 同一 runId 只入库一次 |
| 第二战失败 | 第一战临时奖励也丢失 |
| 新一场战斗 | 保留生命、耐久和剩余物品，清空剑势、灼烧、护盾和破绽加成 |

### 15.2 最低统计项

每场记录：

- 敌人 ID、回合数、胜负、开始和结束生命。
- 四招式使用次数、用药次数。
- 防御吸收伤害、打断次数、造成伤害和灼烧伤害。
- 剑势生成、消耗、溢出数量。
- 属性石和耐久消耗。
- 持有强化和随机种子。

每局记录：

- 第几战撤离或失败。
- 带出奖励、剩余物资。
- 每次提供的强化候选与实际选择。
- 收藏是否解锁成功。

### 15.3 第一轮怎么调

1. 关闭注灵和强化，先检查四招式与三敌人的基础关系。
2. 比较纯攻击、偏守势、按意图应对三种行动策略，不能只跑最优策略。
3. 再逐个开启强化，检查是否产生新的行动选择。
4. 再加入属性石与疗伤丹，检查是否有值得使用、也有值得节省的场景。
5. 最后看三战累计损耗、撤离位置和奖励收益。

每次只调整一类变量，不同时改招式、敌人生命和物资数量。

推荐先观察普通遭遇结束后的生命损失是否存在可辨认的策略差异；不把“每场固定损血多少”当作硬指标。

出现以下情况应回到规则设计，而不只是微调数字：

- 大部分局势都用同一个招式。
- 守势积累剑势再贯虹，几乎总是最优循环。
- 破势总比贯虹好，或者完全没人用。
- 贯虹配属性石成为唯一值得注灵的招式。
- 厚土或反击让守势循环几乎无损，同时效率也很高。
- 两次强化后打法没有变化，只是通关更快。
- 无论剩余生命和奖励如何，玩家都必定打完三场。

### 15.4 本次初步数值核对

已经用独立的简化计算检查三种行动策略，不包含强化、物品和注灵。每场均从 50 生命、0 剑势开始，结果如下：

| 敌人 | 策略 | 回合数 | 结果 | 剩余生命 |
| --- | --- | --- | --- | --- |
| 灵鼠 | 只用剑击 | 4 | 胜利 | 30 |
| 灵鼠 | 剑势不足用守势，足够用贯虹 | 6 | 胜利 | 42 |
| 灵鼠 | 按意图应对 | 6 | 胜利 | 42 |
| 妖兔 | 只用剑击 | 5 | 胜利 | 22 |
| 妖兔 | 剑势不足用守势，足够用贯虹 | 9 | 胜利 | 30 |
| 妖兔 | 按意图应对 | 9 | 胜利 | 44 |
| 守卫 | 只用剑击 | 7 | 失败 | 0 |
| 守卫 | 剑势不足用守势，足够用贯虹 | 12 | 失败 | 0 |
| 守卫 | 按意图应对 | 15 | 胜利 | 50 |

“按意图应对”的具体策略：

- 剑势不足时，敌人将造成伤害则守势，否则剑击。
- 剑势足够时，敌人当前意图可打断则破势，否则贯虹。

这只是规则与数值的初筛，不是客户端实机验证，也不是最优策略搜索。

当前已经能看到两个需要优先验证的问题：

- 妖兔的省血打法达到 9 回合，超过普通遭遇的观察目标。
- 守卫可以用 15 回合固定应对实现无损；虽然操作策略确实影响胜负，但可能过长且容易机械重复。

因此本文数值不能直接当正式平衡值。阶段 A 应继续比较“缩短妖兔和守卫生命”“提高守卫普通攻击压力”等单变量方案，并检查消耗品能否提供有价值的提速选择。

不能只因防御策略能通关，就认定战斗有趣；也不能只因玩家无损，就立即处罚正确应对。还要结合节奏、操作重复度和整局资源取舍判断。
