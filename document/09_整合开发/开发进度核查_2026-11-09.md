## 2. 优先处理的问题

### P1：截止边界与超时失败不成立

- `expireMap()` 只有地图页每秒调用，离开地图进入战斗、起始选择或构筑页后不继续统一执行；加载时也没有先处理截止。
- 在恰好 `deadlineAt` 时提交战斗行动，仍返回成功，回合修订从 0 变 1，局状态仍是 `battle`。
- 战斗中显式调用 `expireMap(deadlineAt)` 报“行动记录或统计存档无效”，未能提交失败结算。结算把局改成失败，却保留进行中战斗；报告校验要求失败必须对应战斗死亡，拒绝超时这种终局原因。
- 已到撤离点后，在截止时刻提交撤离仍成功，局变成 `extracted`。

专项复现 `M01-M03`。证据：[地图轮询](../../src/script/module/expedition/view/SkillBattleMapView.ts) 第 22 行起、[超时与撤离入口](../../src/script/module/expedition/manager/ExpeditionManager.ts) 第 330、342 行、[报告校验](../../src/script/module/expedition/utils/ExpeditionSaveUtils.ts) 第 343 行起。必须先设计统一截止事务和非死亡终局，而不是只补一个界面定时器。

### P1：主流程尚不是新版战斗

运行中的玩家快照只有 `hp/maxHp/block`，没有 MP。有效招式仍为剑击、守势、贯虹、破势；贯虹/破势消耗剑势，主流程仍允许属性石注灵。

普攻、防御未独立于借法：构筑会过滤 UI 可见技能。固定种子 42 起始只选贯虹后，唯一装配主动需要 2 剑势而初始为 0，界面没有独立通用普攻/防御来养势。管理器进入地图战斗时又使用完整武器技能配置，说明 UI 装配限制与计算层许可也未统一。

`weaponAttributeMultiplier()` 虽返回零耐久半值，但没有接入伤害/护盾属性计算；不能把函数存在算作武器属性方案已落地。当前无武器战斗也被固定武器 ID 与存档校验约束。

专项复现 `B01-B02`。证据：[运行时契约](../../src/script/module/skillBattle/types/SkillBattleTypes.ts)、[战斗公式](../../src/script/module/skillBattle/utils/SkillBattleFormulaUtils.ts) 第 54、68、151 行起、[装配过滤与地图入战](../../src/script/module/expedition/manager/ExpeditionManager.ts) 第 62、439 行起。

### P1：构筑记录与战斗效果未连接

- 花 1 点把剑击升至 `+1`，保存档位成功，但预览伤害仍为 `6 → 6`；档位只被保存和显示，没有传入战斗效果。
- 领取“初照”后第一次剑击的增势仍为 `1 → 1`，被动 ID 未参与战斗公式。
- 正常战胜普通节点后道韵仍为 0；`awardDaoyun()` 是可手动调用的接口，胜利流程没有接入普通 10 / 精英 20。
- 全部被动收齐后再次奖励 10 道韵，余额仍从 0 变 10，未停止累积。
- 当前四招被按序分为剑道两招、土道两招，不是正式道性/技能池。运行数据内确有土道 101-105 的五条记录，但它们未进当前武器技能池，更不代表土道提案已获批准。
- 普通战后继续发旧六强化中的候选；这与新主动五档/被动体系尚未完成统一。

专项复现 `C01-C04`。证据：[构筑配置](../../src/script/module/expedition/utils/ExpeditionConfigUtils.ts) 第 38 行起、[档位/被动逻辑](../../src/script/module/expedition/utils/ExpeditionBuildUtils.ts)、[胜利处理](../../src/script/module/expedition/manager/ExpeditionManager.ts) 第 400 行起。

### P1：恢复点有真实保存故障

沿 `b1 → b2 → borrow1 → recovery1` 到达恢复点，实际 HP 为 28/50。尝试恢复报“存档结构或状态不一致”，HP 仍是 28，事务没有提交。

原因是恢复修改当前战斗快照 HP，但历史战斗行动重放仍计算出旧 HP；`validate()` 第 106 行要求两者完全相同。仅有节点分支和“恢复两成生命”文案不能证明恢复可用。即使修复保存，当前代码仍缺 MP 恢复。

专项复现 `M04`。证据：[恢复处理](../../src/script/module/expedition/manager/ExpeditionManager.ts) 第 313 行起、[快照与重放一致性](../../src/script/module/expedition/utils/ExpeditionSaveUtils.ts) 第 104 行起。

### P1：物品与失败损失仍是旧模型

搜索节点一次调用立即给物并标记完成，没有逐件搜索进度；战斗奖励直接加入最多六件的列表，满六件后跳过后续奖励，不存在地面溢出和返取。

失败会清除法囊与本局战利品，但保留 `profile.weaponId` 和耐久；专项夹具超时失败后武器 ID 仍为 1，与“所有装备失败掉落”冲突。新版安全两格和装备禁入也未接入。

专项复现 `M05/I01`。证据：[搜索/奖励/结算](../../src/script/module/expedition/manager/ExpeditionManager.ts) 原第 307、411、464 行起；当时旧 `module/inventory/InventoryManager.ts` 仅连接旧 `BattleData`，未连接当前秘境流程。该无入口旧模块已在后续 UI/资源整理中删除，新三空间尚未因此实现。
