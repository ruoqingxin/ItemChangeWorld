## 3. 运行时契约建议

下列为待实施设计，不强制另造一套命名；优先在现有 types 与 Data 上扩展，具体规则以获准确认包为准。

| 对象 | 必须表达的事实 | 不得沿用的旧假设 |
| --- | --- | --- |
| 行动输入 | 普攻、防御、已装配主动、独立药品；药品引用实际 UID | 普攻/防御占借法槽；技能 ID 等于 UI 槽位 |
| 令牌 | 当前战斗 ID 与状态修订号；用药成功即使旧预览失效 | 同回合的预览永远有效 |
| 回合与药品机会 | 主行动次数/回合与全部提交次数分开；用药机会随本回合持久化 | `round = revision + 1`；刷新页面恢复用药机会 |
| 玩家/武器 | HP/MP 上限与余量、角色基础属性、武器可空及其实际属性/耐久 | 固定武器 ID；零耐久把角色总能力减半 |
| 局内构筑输入 | 借到的道、主动真实 ID/档位、已得被动；战斗中只读 | 只过滤技能列表，档位与被动不用进公式 |
| 战内临时状态 | 势、锋意、凝锋待兑现增强、初照/息锋、递锋前序身份、剑痕伤害与剩余次数 | 标记只放在 Presenter；每次读取状态临时重算 |
| 敌人 | 实际 HP/盾、当前意图索引或固定结果、明确蓄力标签 | 用旧 interruptible 代替蓄力；提交后重抽 |
| 跨战 carry | HP/MP、武器及耐久、斗法匣实际库存、同局构筑；按规则重置战内标记 | 跨战自动补 MP/修武器；把初照/剑痕带入下场 |
| 预览 | 本体、前置削盾、锋意、被动、剑痕分项；即时/延迟、资源与费用、失败原因 | 把药品当敌方回合；把延迟伤害算进即时击杀 |
| 保存/报告 | 已提交输入序列、版本/规则签名、初始构筑与必要快照、恢复事件及终局原因 | 只存技能 ID，重放时拿已被清空或升级后的构筑 |

重放尤其要保存“该场开战时”的技能档位/被动和必要配置版本，不能用后来强化后的构筑重算之前的伤害。终局清空局内构筑后，历史仍须能独立重放；药品提交、恢复点事件也不能从账本消失。

阶段 1 不提前实现全部仓库，但药品接口必须消费斗法匣真实实例，不增加战斗内跨空间取物入口；武器可空契约也不能隐含失败装备保护。完整物品守恒和失败全掉落仍随阶段 3 实现验收。
