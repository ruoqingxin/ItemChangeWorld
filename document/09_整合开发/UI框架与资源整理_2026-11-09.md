# UI 框架与资源整理

日期：2026-11-09。依据：用户本次要求，通用 UI 框架参照 `E:\xiangqi\client`，保留横屏；整理预制体和资源；废弃所有旧档、不做兼容；删除无用旧实现，但不影响新开发。

本记录是 [实际开发进度核查](开发进度核查_2026-11-09.md) 后的实施补充，不倒改之前的测试成绩。后续仍从 [README](README.md) 进入本目录，不回到历史稿开发。

## 1. 框架边界

- 同步象棋项目的通用 `UIBaseView`、`UIManager`、`UIElements`、`UIEvents`、`UIButton`、`ElementMapper`、`TabCtrl`、按压/激活/文字组件及 10 个元素动画文件，保留本项目脚本 UUID。
- 保留 `games/ui` 目录，不为名称相同而全仓改成 `sfgames`。沿用 GRoot、分层、页面缓存、ElementMapper 绑定、公共按钮、页签和元素动画，不建立第二套业务框架。
- 横屏设计尺寸 1280×720，保持 `SCREEN_HORIZONTAL + SCALE_SHOWALL`；UI 根按设计宽高比适配，不使用象棋的竖屏/1:1 限制。
- 不复制象棋的棋类页面、功能配置排序、加载提示业务、竖屏相机，以及当前没有使用的额外装饰组件。加载状态在通用层派发事件，错误上报适配本项目 API。
- 补齐重复初始化保护、已关闭缓存回收、页签子页销毁、关闭中页面保护、立即关闭、关闭后重开、多动画全部结束后只回调一次。修复父页存在判断及负 padding。

## 4. 存档与缺陷修复

本次废弃所有旧版本游戏存档。唯一新键为 `nowchange.skill-expedition.current.v2`，结构版本 2；启动清理当前 origin 的其他项目存档键，保留其他应用数据和新版进度。清理范围、不同 origin 的执行时机及后续维护边界见 [工程与存档约定](09_工程配置与存档约定.md)。

删除旧档字段补齐、三战转地图和宽松签名兼容。新版不读取旧存档内的物资、余额、活动局或报告；无 `?legacy=1` UI 入口。部分短遭遇纯逻辑夹具保留用于隔离公式和事务测试，不是另一套产品入口。

本轮关闭的核查缺陷：

- 可达且未击败的敌人点击直接入战；撤离仍确认，未揭示/被阻挡敌人不进入。
- 起始选择、构筑、地图、战斗提交和撤离均先检查绝对截止；统一会话定时、前台恢复与重载也检查，达到截止先失败。
- 超时作为独立终局原因保存，不伪造生命归零或敌人击杀；战斗中、战后和离线超时可保存/恢复；已经成功撤离的结局不被之后超时覆盖。
- 地图回血进入可重放的恢复记录，记录节点、战斗索引和前后 HP；恢复后的快照可校验、重载、带入下一战，不通过放弃行动记录校验绕过错误。满血不消耗恢复点。
- 存储写入失败不替换权威内存状态，超时结算可重试且不会重复结算。
