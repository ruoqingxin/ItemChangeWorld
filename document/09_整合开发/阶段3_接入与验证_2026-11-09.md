后续用户否定本报告对应的点选式储物交互，并上传视频要求真实拖动/旋转。以下成绩仅记录当时版本，不代表拖拽需求已满足；当前交互与重新实测以 [视频修正记录](储物拖拽与旋转_2026-11-09.md) 为准，原规则/存档边界继续保留。

## 1. 可玩入口与边界

本机预览：`http://127.0.0.1:18120`。默认储物演练，阶段 1/2 的独立开发回归入口为 `?stage=1` / `?stage=2`，不在玩家界面增加新旧规则切换。

显式建立演练库存 → 装备/三空间整备 → 入境/起始选法 → 当前节点揭示、拾取、整理 → 新核实际用药 → 战后借法与修补 → 撤离或失败 → 带回/损失/消耗账本。

演练库存可显式重新建立，不是账号永久仓库或初始赠送。节点只按已胜战数开放前进与返取，不是 R07 正式路径/搜索图；本次“揭示来源”不冒称一秒逐件搜索。六场构筑沿用阶段 2 夹具，未设计正式随机掉落或八至十五战首图。默认实测完成首战与撤离；多战携带和极限分支由隔离规则夹具覆盖，不宣称默认六战平衡通关。

## 2. 实际实现

| 模块 | 本轮实现 |
| --- | --- |
| `NewInventoryTypes/ConfigUtils` | 从三张生成表读取模板、规则与显式来源；11 种模板与逐份 UID，模板和实例分离 |
| `NewInventoryRules` | 唯一实例位置、矩形/旋转/相交/类别校验、5×1/2×1 与 6×5/8×6、武器/容器换装、真实使用、地面与终局账本 |
| `NewInventorySession` | 单档完整命令重放、配置比较、修订/原文比较、重入锁、最后写前截止、写成功再发布、损坏原文保留 |
| `NewBuildRules` | 阶段 3 传入实际 HP/MP/武器/斗法匣；不传实际携带的阶段 2 回归仍沿用其隔离供给 |
| `NewInventoryPanel` | 继承现有构筑面板，复用 UIManager/UIBaseView/ElementMapper，整备/当前地面/终局账本、虚影与换包投影、长名适配和倒计时 |
| Start/Settlement prefab | 左侧装备/斗法匣/归真匣，中间完整纳虚器网格/详情，右侧来源分页筛选；战斗页沿用现有预制 |

所有实例仅有一个权威位置：仓库、装备位、三空间、节点地面、已消耗或已损失。堆叠为一，换武器必须指定旧武器去向，耐久不重置。换包逐件安排原内容；大换小不合时整笔拒绝，可在未提交投影中重排，局内旧本体落当前地面。无容器仍能入境，容器不得嵌套或随身备用。

战斗从实际斗法匣构造药品，不自动补满；修补工具在战斗显示为战外使用且禁用。用药、消耗实例与本回合机会一次提交；主行动失败不退已用药。战外可从三个携带空间用实际药品/修补工具；修补仅当前武器 +20 截上限，满耐久/无武器不扣物。

撤离只带回当前携带物；死亡、放弃与超时仅保护合规归真匣，装备和其他携带物损失，地面物清局。账本分库存、实际带回、实际损失、已消耗；终局同时清本局构筑并锁定，恢复不重复入库。

## 3. 源表与资源

配置工程 `E:\NowChange\config` 的 N 工作簿新增 `inventory_item`、`inventory_rule`、`inventory_fixture`，注册后运行包从 32 到 35 表。

核查发现 W/S 源表含未进入已交付运行包的历史提案，直接全量生成会改旧 item/skill。未修改 W/S 文件，改在 N 表增加 `legacy_item` / `legacy_skill` 回归页，并只调整这两项注册输入：复用原源表中与旧运行包一致的 11 个物品、4 个技能。原 N 九页值/公式未改；源表检查无公式错误，新增页与注册预览已目检。item/skill 独立导出也随正常生成重建，不将其历史漂移再写回运行包。

使用系统 .NET 执行原 Luban DLL，然后运行 `packall.js` 并同步客户端；没有手改 schema/bin。仓库批处理依赖的局部 `.dotnet` 不存在，本轮使用 `C:\Program Files\dotnet\dotnet.exe`，没有借此修改生成脚本。

## 4. 保存与计时契约

单一键 `nowchange.stage3-inventory.v1` 保存：配置/资格/种子、全部实例位置/实际耐久/账本、构筑随机与候选、完整战斗、节点揭示、命令时间、整局修订、起点截止与结算。

候选状态完整重放并与快照比较，写前原文比较防旧页覆盖，最后再检查截止，一次 `setItem` 成功后才发布内存。准备不计时，入境起算 1200000ms，初始选择、整理、预览、后台和离线计入；达到截止先超时。撤离虽生成终局候选，也必须过最后写前截止检查。

不清理或迁移阶段 1/2/v2/其他应用键，不调用 `localStorage.clear()`。损坏原文保留并阻止继续，只有明确二次确认才删除阶段 3 自身键。原文比较不是跨窗口强锁，本地时钟与命令重放不承诺防篡改、可信时间或跨端事务。
