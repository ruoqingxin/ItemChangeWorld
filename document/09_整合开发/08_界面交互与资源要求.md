# 界面交互与资源要求

## 1. 页面与流程

局外整备 → 入境抽两道 → 起始主动 → 节点地图 ↔ 战斗/搜索/借法/储物 → 撤离或失败结算 → 统一库存与学习/商店/维修/成长 → 再整备。

页面布局未全部定稿，以下是已确认信息与交互约束，不强行新增专用参悟页或借法升级建筑。

| 页面 | 必须表现的信息与状态 |
| --- | --- |
| 整备 | 血蓝上限、武器属性/耐久、纳虚器、三空间、实际携入与失败保护；两道入境后决定 |
| 起始 | 当前两道、有效重抽状态、三名合资格主动、必须选一个；无其他组合不播广告 |
| 战斗 | 敌人当前意图、双方血盾、灵力、剑势/锋意、通用行动、最多三主动、斗法匣实际物品 |
| 药品 | 本回合药品机会、实际恢复量、满状态禁用原因；药后主行动仍可用 |
| 预览 | 本体、锋意、被动、持续伤害分项，区分即时/延迟；下一行动资源和耐久变化 |
| 构筑 | 主动基础/+1 至 +5，被动无等级，来源与触发条件，道性单列 |
| 替换/强化 | 新旧效果与继承档位同屏比较；确认前返回不刷新，战外展示下一档，战内只读 |
| 地图 | 已揭示范围内的完成、可达、类别、撤离、已悟尽/无可借内容；剩余时间与两次预警 |
| 搜索/拾取 | 未知黑影、逐件进度、揭示/拾取状态、容量不足及空间分配，不偷看未知内容 |
| 储物 | 实际拼图、旋转、禁放原因、容量与保护，装备不可塞归真匣，不仅用颜色说明 |
| 撤离确认 | 保留/损失预期、临时构筑结束；可取消继续，未提交计时不停 |
| 失败结算 | 原因、归真匣实际保留与损失，不能显示铁剑专属保护 |
| 局外库存/学习 | 发现未带出、带出资格、已学、高阶已收录但不可借分开；学习实际扣一本 |
| 商店/维修 | 今日有限货架与常备货源明确，库存/资格/愿力价格/实际扣款与维修效果 |

## 2. 不得误改的交互

- 点击可达未击败敌人直接入战，无二次确认；不因此取消撤离、替换或主动放弃的确认。
- 战外才能整理与强化；战斗中不能从其他空间补斗法匣，不能借构筑面板绕过只读。
- 取消预览、查看、返回候选不扣物、不刷新结果，也不暂停倒计时。
- 提交处理中锁定重复操作，失败反馈不能伪装成功；恢复保持上一已提交状态。
- 广告异常不扣机会、不改两道、不强制退出，但计时继续。
- 无可用内容不弹空面板；奖励耗尽提示只在已揭图范围，不能借状态提前泄露地图。
- 不显示注灵操作、虚实转换按钮、双仓分页或强制形态标记。

## 3. 资源与参考

先准备可辨认角色、敌人、场景、技能/物品图标、节点状态和必要反馈，再逐步精修；不等全部美术才验证，也不以占位图声称正式美术完成。

全部原 UI 参考图均保存在 [原始快照/UI参考](参考资料/原始快照/UI参考)，逐文件入口见 [来源清单](来源清单.md)。图片属于风格与布局参考，不是规则证据，不从图片推导槽位、容量、技能数量或交互权限；本轮未逐张审美评定或指定哪张为最终设计。

桌面及手机输入均需真实点击/触摸验证：按钮、返回、替换、旋转、长文本、滚动、弹窗层级和提交锁定。既有浏览器面板、完整工程入口与正式平台分别记录验收范围，不能互相替代。
