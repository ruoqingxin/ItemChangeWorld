# 界面交互与资源要求

## 1. 页面与流程

局外整备 → 入境抽两道 → 起始主动 → 节点地图 ↔ 战斗/搜索/借法/储物 → 撤离或失败结算 → 统一库存与学习/商店/维修/成长 → 再整备。

页面布局未全部定稿，以下是已确认信息与交互约束，不强行新增专用参悟页或借法升级建筑。

| 页面 | 必须表现的信息与状态 |
| --- | --- |
| 整备 | 血蓝上限、武器属性/耐久、纳虚器、三空间、实际携入与失败保护；两道入境后决定 |
| 起始 | 当前两道、有效重抽状态、三名合资格主动、必须选一个；无其他组合不播广告 |
| 战斗 | 敌人当前意图、双方血盾、灵力、剑势/锋意、通用行动、最多三主动、斗法匣实际物品 |
| 药品 | 本回合药品机会、实际恢复量、满状态禁用原因；药后主行动仍可用 |
| 预览 | 本体、锋意、被动、持续伤害分项，区分即时/延迟；下一行动资源和耐久变化 |
| 构筑 | 主动基础/+1 至 +5，被动无等级，来源与触发条件，道性单列 |
| 替换/强化 | 新旧效果与继承档位同屏比较；确认前返回不刷新，战外展示下一档，战内只读 |
| 地图 | 已揭示范围内的完成、可达、类别、撤离、已悟尽/无可借内容；剩余时间与两次预警 |
| 搜索/拾取 | 未知黑影、逐件进度、揭示/拾取状态、容量不足及空间分配，不偷看未知内容 |
| 储物 | 实际拼图、旋转、禁放原因、容量与保护，装备不可塞归真匣，不仅用颜色说明 |
| 撤离确认 | 保留/损失预期、临时构筑结束；可取消继续，未提交计时不停 |
| 失败结算 | 原因、归真匣实际保留与损失，不能显示铁剑专属保护 |
| 局外库存/学习 | 发现未带出、带出资格、已学、高阶已收录但不可借分开；学习实际扣一本 |
| 商店/维修 | 今日有限货架与常备货源明确，库存/资格/愿力价格/实际扣款与维修效果 |

## 2. 不得误改的交互

- 点击可达未击败敌人直接入战，无二次确认；撤离、构筑替换和主动放弃仍确认。装备替换遵循下述最新直接拖动规则。
- 战外才能整理与强化；战斗中不能从其他空间补斗法匣，不能借构筑面板绕过只读。
- 取消预览、查看、返回候选不扣物、不刷新结果，也不暂停倒计时。
- 提交处理中锁定重复操作，失败反馈不能伪装成功；恢复保持上一已提交状态。
- 广告异常不扣机会、不改两道、不强制退出，但计时继续。
- 无可用内容不弹空面板；奖励耗尽提示只在已揭图范围，不能借状态提前泄露地图。
- 不显示注灵操作、虚实转换按钮、双仓分页或强制形态标记。
- 储物按用户上传视频落实为双侧实体网格与真实拖拽：图片跟随鼠标/手指，完整占格落点高亮，旋转同时改变图片和尺寸，普通搬运松手保存，禁放回原位。桌面 R/右键与旋转图标可旋转，触屏可保持一指拖动并用第二指点旋转。取消、系统触摸取消、切后台、关闭页面或到期不能意外落物。
- 根据用户后续明确要求，拖动物品在格区悬停时自动判断横竖：当前方向无法放入、反向可合法放入才等待后转 90 度，默认 400 毫秒（可调）；同格偏移超过 6 个设计像素或进入另一格重新计时，容忍小幅抖动。不来回翻转，不绕过类别/碰撞限制，不替玩家找其他落点；手动旋转优先。同位置手动操作后不自动反转，移动后再重新判断。松手仍按当前合法方向校验，不在松手时补做自动旋转。
- 用户进一步明确装备区也必须显示实际占格，所有格子统一大小。武器位显示 2×3 六格、纳虚器位显示 2×2 四格，空位保留格线，装备后图像覆盖完整实体尺寸，不能缩成一格缩略框。用户随后要求完全参考 `765fb0fb4ccbdaf0327f7db10f28d53c.jpg` 的格子大小：原图 2510×1156，单格约 110 像素、占屏宽约 4.4%，折算 1280 设计宽度采用 56 个设计像素格距（54×54 格图加 2 像素间隔），覆盖此前 50 格距。装备、斗法匣、归真匣、背包、仓库/地面、拖拽图片与高亮统一该尺寸；面板和说明区同步留出空间。56 是当前布局参数，不改变容量、实体占格、装备位或存档。纳虚器外部四格与内部 6×5/8×6 容量明确区分。
- 用户最新明确换包、换武器也无需额外确认：合法松手即完成整笔换装。换小纳虚器自动重排，能装的留包内，装不下的局外退仓、局内放当前已揭示地面，完成后显示留包/退回数量；换武器时旧武器回新武器来源位置。按住、悬停和旋转不提前保存，取消/非法松手/写失败回原状态；不再进入换包规划或旧武器去向确认。点选换装备辅助入口同样直接完成。撤离/放弃仍保留确认，不照搬视频商店、货币、承重、药品堆叠、装备位或容量。
- 2026-11-09 用户进一步明确去掉物品图片上叠加的占格数字（如 1×2、2×2），覆盖三空间、仓库/地面、结算列表和拖动图片；装备下方/详情中的尺寸说明和原有武器耐久显示保留。选中与拖动合法/禁放描边改为圆角矩形，当前四角半径 6 设计像素、线宽 2，匹配品质框外形；格距、真实占格、旋转、颜色语义及保存规则不变。

## 3. 资源与参考

2026-11-09 用户明确要求：通用 UI 框架以 `E:\xiangqi\client` 为参照，当前项目保留横屏。继续使用 `UIManager → UIBaseView → UIElements/ElementMapper`、`UILayer`、公共按钮和元素动画组件，不引入第二套 UI 系统。设计尺寸为 1280×720、`SCREEN_HORIZONTAL + SCALE_SHOWALL`；不照搬象棋的竖屏/1:1 根尺寸，也不复制棋类业务或竖屏相机。

预制体在 `assets/ui/prefab/common/<control>` 与 `assets/ui/prefab/module/<feature>`；小图在 `assets/ui/atlas/common`、`atlas/module/<feature>`；背景和大面板在 `assets/ui/texture/common`、`texture/<feature>`。模块名与代码目录一致；使用语义文件名，资源移动必须连同 `.meta` 保留 UUID，并同步路径和依赖表。原图、旧切图和备选稿放项目 `art/reference`，不得混入运行时图集。公共品质框等后续储物可复用素材可保留在明确的公共资源目录。

全屏页面使用 `MapperTypeEnum.Fullscreen`，弹窗才使用 mask；节点绑定沿用 ElementMapper，页面创建、打开、关闭和释放由基类管理。禁止恢复已删除的旧生成器覆盖当前预制体。目录细节、清理清单和当前验证见 [实施记录](UI框架与资源整理_2026-11-09.md)。

先准备可辨认角色、敌人、场景、技能/物品图标、节点状态和必要反馈，再逐步精修；不等全部美术才验证，也不以占位图声称正式美术完成。

全部原 UI 参考图均保存在 [原始快照/UI参考](参考资料/原始快照/UI参考)，逐文件入口见 [来源清单](来源清单.md)。图片属于风格与布局参考，不是规则证据，不从图片推导槽位、容量、技能数量或交互权限；文档初次整合时未指定最终设计。

2026-11-09 用户进一步指定 `E:\资源\修仙宗门搜打撤` 的本地图片和原 `document/UI参考` 用于后续开发。已核实实际图片目录是 `extracted_assets/images`；最初精选 52 张候选存入 `art/reference/cultivation`。随后用户整包批准阶段 3，实际选取 22 张现成 PNG 接入运行资源：小图/控件在 `assets/ui/atlas/module/inventory`，四张大面板/条带在 `assets/ui/texture/inventory`，来源清单位于前者的 `sources.json`。保留原框架的 Start/Settlement prefab，不为储物另建 UI 系统或整屏图片。没有绘制/生成新位图，没有整包导入原游戏资源。效果图用于随身空间/仓库/地面并排布局，不沿用卡组、双币、药品堆叠或付费锁页。来源、临时代图和发布权利未核实边界统一见 [资源选型记录](资源选型与UI参考_2026-11-09.md)；本轮实测见 [阶段 3 接入](阶段3_接入与验证_2026-11-09.md)。

桌面及手机输入均需真实点击/触摸验证：按钮、返回、替换、旋转、长文本、滚动、弹窗层级和提交锁定。既有浏览器面板、完整工程入口与正式平台分别记录验收范围，不能互相替代。

2D 图片导入必须明确使用精灵纹理（`textureType: 2`）、`sRGB: true` 与 `premultiplyAlpha: true`，保留已有 UUID 和九宫参数。不能以直接加载 PNG 的预览正常，推定 IDE 导入正常；缺省纹理设置曾造成 IDE 面板发灰、物品透明区域发白。现行修复与实际工程入口验证见 [颜色差异修复](资源选型与UI参考_2026-11-09.md#9-ide-运行与预览颜色差异修复)。

用户随后明确要求后续新增图片统一使用这三个设置。项目原生默认值已在 `settings/EditorSettings.json` 设为 `textureType: 2`，对应 IDE「项目设置 → 预设值 → 纹理类型 → 精灵纹理」。当前 IDE 的精灵预设自动启用 sRGB/预乘透明，无需另设两个不受支持的项目字段或安装监听插件。此默认值只影响新导入且未指定独立纹理类型的图片，不批量覆盖已有 `.meta`、UUID、九宫或明确的特殊纹理设置；后续若引入 3D 法线/数据贴图，应单独使用相应类型，不照用精灵预设。外部修改项目预设后重开项目，让 IDE 读取设置。

### 3.1 物品品质框

2026-11-09 用户最新明确：物品品质采用普通白、优秀绿、精良蓝、稀有紫、史诗金、传说红六档，规则以 [物品品质](05_物品储物与终局结算.md#11-物品品质) 为准。本次所指是物品品质框，不是新增凭证框或凭证玩法。

- 品质框仅需六张图片，每档一张；使用九宫拉伸适配不同物品的实际占格，不按 1×1、1×2、2×2、2×3 等尺寸分别制作，也不为横竖方向另出图片。
- 九宫拉伸保留四角，边缘沿对应方向延展，中部适配目标区域；不能将整张品质框直接非等比缩放。物品旋转改变占格宽高时，框按新的宽高重新拉伸，物品图片仍遵循已有同步旋转规则。
- 优先复用可用的现有公共品质框；候选“大框六种、小框五种”只说明素材库存，不决定本项目品质档数。最终只需一套六档品质框图片，不要求各出一套大框和小框。
- 用户随后用目录与截图指定 `art/reference/cultivation/frames/quality-1.png` 至 `quality-6.png`，按 1-6 对应白、绿、蓝、紫、金、红。已将六张原图原字节复制至 `assets/ui/atlas/module/inventory`，不使用 `compact-quality-*` 小框，不重绘或重新调色。
- 采用上下左右各 8 像素、中心拉伸的九宫参数（Laya `sizeGrid: [8,8,8,8,0]`），写入图片 `.meta`；运行时补齐原 PNG 浏览器预览的九宫纹理与绘制指令，不能仅有参数而仍普通缩放。装备、三空间、仓库/地面、结算列表与拖动图像按完整占格显示，战斗斗法匣物品图标使用同一套框。
- 选中描边、拖动合法/禁放高亮独立于品质底图，不用圆形框替换选中物品，不给品质图片叠加红绿染色。无物品的装备位仍显示原格阵，无品质框。当前模板未指定品质时显示普通白框，详情标明品质；只作显示回退，不修改模板、物品属性或存档，也不擅自给现有物品分配高品质。实际接入、来源与验证边界见 [品质框接入记录](资源选型与UI参考_2026-11-09.md#8-六档品质框实际接入)。
