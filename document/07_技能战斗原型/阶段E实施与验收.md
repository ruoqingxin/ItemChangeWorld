# 阶段 E：收藏解锁与测试统计

日期：2026-11-05  
依据：《固定站位回合制战斗实施方案.md》阶段 E。  
状态：实现、类型检查、逻辑回归与生产 Laya 面板浏览器验收完成，待人工试玩反馈。基础数值未调整。

## 1. 本阶段交付

- 成功撤离后，在据点物品列表点击残卷“收藏”，消耗一个独立实例，永久记录收藏标记 1。
- 后续新局开放余势、破绽，候选池从四项扩大到六项；仍随机无放回三选一，不保证每次出现新强化。
- 收藏不改变已结束秘境的出发池、实际候选或选择记录。活动秘境禁止收藏，也不提供战斗中撤离或免费补给入口。
- 已收藏的重复残卷仍保留，显示“已收藏 · 重复残卷留存”；再次点击明确提示，不消耗、不写档。不做出售、分解或共鸣。
- 收藏的物品消耗、永久标记及来源秘境的解锁记录写入同一份快照。写入失败全部回滚。
- 原生 Laya 界面新增“战斗记录”，可从战斗、战后和据点进入，切换统计与行动日志、翻页、查看最近历史局。
- 接入可复现的平衡探测脚本、原始 JSON 数据及《阶段E平衡测试报告.md》。

阶段 D 配置已有收藏物品与强化所需标记，阶段 E 沿用现有 Excel / Luban 配置与二进制包，没有改表、改生成代码或改正式数值，也没有新增武器、借法、背包经济或修仙成长。

## 2. 记录与统计

每次成功确认行动时，将行动与整回合战斗结果、胜负、奖励和结算放入同一份原子存档。预览、取消、无效操作、过期确认、动画播放、跳过、关闭界面都不写入行动记录。

每场保留开始快照与已确认行动序列，用生产纯规则重放生成日志和统计，不另写伤害公式：

| 内容 | 口径 |
| --- | --- |
| 敌人、生命与胜负 | 敌人 ID、开始/结束生命、已记录行动回合、进行中/胜利/失败 |
| 四招式与用药 | 每种招式次数、用药次数、实际回复生命 |
| 防守与伤害 | 玩家护盾实际吸收、成功打断、实际承伤、敌人实际失血；灼烧是总失血的子项 |
| 剑势 | 配置产生的总量、实际支付的成本、被上限舍弃的溢出；终局清空不算额外消耗 |
| 物资 | 属性石实例使用次数、实际耐久损耗 |
| 构筑与随机 | 各场持有强化；整局种子；每次实际候选与所选 ID |
| 撤离/失败 | 第几战结束、实际带出奖励、结算保留的法囊 |
| 收藏 | 本局带出的残卷是否成功产生收藏解锁 |

普通直接伤害、注灵和反击均按敌人实际失血计数，不把护盾吸收或过量伤害当作已造成生命伤害。完整事件日志仍能查看原始伤害和吸收。

存档保留当前/最后一局及最近 20 份归档。开启新局时归档上一局，超出范围仅移除最旧统计，不清除仓库、收藏、货币或结算去重记录。当前局行动不截断，存储空间不足时明确报错并拒绝该次提交，不假装保存成功。

尚未结算时，统计显示“未结算”，而非将临时战利品认作已带出。旧残卷在之后的局外收藏，若来源仍在保留记录中，则更新来源局；不能归属的旧档残卷仍能正常收藏，但不伪造历史来源。

## 3. 存档兼容

- 沿用存储键 `nowchange.skill-expedition.v1`，配置签名不变。
- 为阶段 D 存档补充历史列表与记录结构，不清档、不补发物资、不重抽候选。
- 阶段 D 没保存行动，无法还原已经发生的战斗。以载入时安全快照开始记录，并明确标为“旧局记录不完整”，不将缺失历史记成零损耗。
- 只读载入不写盘，下次成功操作时连同记录结构一起保存。
- 旧档中的阶段、物品 UID、耐久、仓库、货币、收藏和当前候选保持不变。
- 新记录载入时重放并与正式战斗快照校验；损坏记录不覆盖原始存档。
- 显式重置测试档仍需二次确认，同时清除统计。

沿用本地单机原型边界：按浏览器来源隔离，不承诺跨设备、跨端口、防修改、多窗口并发或任意未来规则版本迁移。
