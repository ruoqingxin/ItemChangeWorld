第三阶段要新增一个正式的局内背包系统。

定稿规格：

*.txt

*.txt

*.txt

十一、第三阶段前建议先修的代码问题
1. EBattleStatusId 与配置表不一致
当前代码中：

*.ts
TypeScript
export enum EBattleStatusId {
    Power = 1,
    Weak = 2,
    Vulnerable = 3,
    ArmorBreak = 4,
}
但当前 status 表实际是：

status_id	状态
1	力量
2	虚弱
3	中毒
4	灼烧
5	易伤
6	破甲
7	冻结
所以代码应该修为：

*.ts
TypeScript
export enum EBattleStatusId {
    Power = 1,
    Weak = 2,
    Poison = 3,
    Burn = 4,
    Vulnerable = 5,
    ArmorBreak = 6,
    Freeze = 7,
}
否则当前：

*.ts
TypeScript
Vulnerable = 3
ArmorBreak = 4
会导致：

*.txt
Plaintext
易伤误读成中毒
破甲误读成灼烧
这会影响基础伤害、注灵测试和第三阶段战斗掉落验收的稳定性。

2. effect_group 当前应按 effect_define.effect_id 解析
当前配置中：

*.txt
Plaintext
card.effect_group
enemy_intent.effect_group
element_stone.minor_effect_group
写的是：

*.txt
Plaintext
effect_id,value,target,param
其中 effect_id 对应的是：

*.txt
Plaintext
effect_define.effect_id
而不是直接等于：

*.txt
Plaintext
EEffectType
当前代码在 executeEffects() 里直接：

*.ts
TypeScript
switch (Number(effect.effectId)) {
    case EEffectType.damage:
    ...
}
短期能跑，是因为：

*.txt
Plaintext
effect_id 1 = damage
effect_id 2 = gain_block
effect_id 3 = apply_status
刚好和 EEffectType 对上。

但后面的：

*.txt
Plaintext
治疗
失去生命
跳过行动
恢复灵力
已经出现了错位风险。

建议第三阶段前修成：

*.txt
Plaintext
effect_id
↓
effect_define
↓
effect_type
↓
执行逻辑
这样后续扩展掉落、丹药、功法、事件时不会踩坑。

1. 第三阶段名称定为：局内背包与战斗掉落。
2. 局内背包规格为 6×5。
3. 所有物品不可堆叠。
4. 背包不支持旋转。
5. 第三阶段先不做拖拽摆放，拾取时自动找空位。
6. 战斗胜利后生成掉落列表，不自动放入背包。
7. 掉落物生成独立 itemUid。
8. 多个同名掉落生成多个独立实例。
9. 拾取时检查 item.bag_width / item.bag_height。
10. 背包满时拾取失败并提示。
11. 玩家可以丢弃背包物品。
12. 丢弃后释放格子。
13. 灵石不直接掉落，掉落灵石袋。
14. 灵石袋占格，不堆叠，只能撤离后使用。
15. 第三阶段暂不做撤离，所以灵石袋只能放入背包，不能打开。
16. 战斗中不能打开正式背包。
17. 战斗中仍然只能使用临战法囊。
18. 临战法囊继续使用 Debug 初始化。
19. 第三阶段暂不让背包与临战法囊互通。
20. 掉落表新增 drop_table / drop_item。
21. enemy.drop_table_id 接入实际掉落表。
22. 新增一批测试物品：灵草、灵果、赤炎草、灵石袋、功法残卷、普通武器、大刀。
23. 第三阶段不做仓库、撤离、秘境地图、采集、宝箱、炼丹、功法收藏。
